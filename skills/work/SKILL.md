# Work

1. Read only `references/instruction-loading.md` as the bootstrap before interpreting an explicit `$work <mode> -- <request>` invocation or proposing an implicit entry. Public modes are task, revise, migration and execute.
2. For explicit input, call `workspace create --workflow-id invocation` without a requirement ID, save the unchanged text as invocation.txt under the returned pending path, then run `invocation parse --input-file <path>`. Preserve origin explicit; do not choose a path directly under outputs.
3. For an ordinary request suited to Work, first present the proposed mode and exact request for user confirmation. After confirmation, save the strict implicit invocation input (mode, request and confirmation; no schema field) with matching mode/request and confirmed evidence in the returned invocation workspace, then run `invocation confirm --input-file <path>`. Preserve origin implicit_confirmed and the complete confirmation proof; do not fabricate literal `$work` input or infer permission from skill activation.
4. Before the first Source capture, use the portable requirement ID explicitly supplied by the user or a formal handoff. If no ID is available, ask the user to provide and confirm it before source capture preview/approval; never infer an ID from a filename or wait for a complete TASK candidate. Task then captures the exact requirement payload once as immutable Source, then independently confirms hierarchy, external skills and main acceptance before planning TASKs. Use the CLI Source capture preview/approval and returned snapshot; all later Task discussion, drafts, progress and formal candidates reuse that fixed planning_source. Never fetch or normalize a replacement Source silently.
5. For Task, Revise and Execute, call `workflow status` or `workflow next`, require VALID routing and verify the selection manifest fingerprint. Load exactly required_instruction_sources in source_order for the current next_action. Revise uses the internal Specification workflow. Migration loads `references/instruction-loading/artifact-migration.md` and its dedicated commands; it does not enter ordinary lifecycle routing.
6. Keep user decisions and authorization in the main flow. Give an isolated worker only the canonical operation envelope and routed sources; accept structured results/evidence. Private roles, snapshots, invocation confirmation and validation grant no write or execution approval.
7. Re-run routing on operation, state, lifecycle, selection, authorization, role or formal-event changes. Stop dependent operations on REVIEW_REQUIRED, source/state drift, missing sources, insufficient authorization or incomplete envelopes. Never scan or preload entire instruction, workflow or subagent directories, and never reuse a failed/recovery context.
