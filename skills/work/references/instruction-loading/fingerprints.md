# Canonical fingerprints

1. Formal TASK index/items, Execution index, Attempt and Correction are standalone canonical JSON objects without Markdown wrappers. Use contract-defined key order, two-space indentation, UTF-8 without BOM, NFC, LF and one trailing LF. Encode SHA-256 as 64 lowercase hexadecimal characters.
2. Source raw fingerprints bind the exact original captured bytes, including BOM, whitespace and line endings. Never normalize raw Source content or immutable historical evidence to fit a current fingerprint. Manifest and completion-marker verification additionally bind size, path and snapshot identity.
3. `task_index_sha256` and `task_item_sha256` bind exact canonical document bytes. `task_collection_sha256` is the structured fingerprint of `work-task-collection-fingerprint/v1`, containing index SHA and ordered item IDs/SHAs. Query its registered description for the actual fingerprint structure; the derived object is not another formal artifact.
4. Instruction source content uses the canonical text BOM/NFC/LF/trailing-LF rules. Save source `kind`, `logical_name`, `canonical_sha256` and its verified `compatibility_revision`; do not save absolute paths, source layers, platform separators or working directories in selections.
5. Preserve actual instruction load order: `work.instruction-loading`, `work.workflow.<mode>`, general/hierarchy instructions and routed references. Frame with ASCII `WORK-INSTRUCTIONS-SHA-256-V1\n`; each source starts with `S`, then UTF-8 byte-length-prefixed scope (`task` or `execute`), kind, logical name and canonical content. Append LF per source and finish with `END\n`; hash the complete frame.
6. A source kind is workflow/instruction/reference. Instruction logical names contain the mode and dot-joined hierarchy; references use globally unique declared names. Document instruction fingerprints use the first-occurrence union applicable to all TASKs; per-TASK fingerprints use only that TASK's sources. Do not alphabetically sort either set.
7. Hierarchy and external skill selection fingerprints are independent from instruction and Source fingerprints. Preview approval also binds the complete reviewed candidate, original evidence, current bindings and applicable history; matching one document SHA does not establish transaction approval.
8. Existing Attempt/Correction headers and bytes remain historical evidence after a revision or migration. Revalidate current bindings and invalidate affected acceptance results instead of rewriting historical hashes to current values.
