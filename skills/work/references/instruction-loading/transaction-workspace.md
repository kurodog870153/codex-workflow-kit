# Transaction workspaces


1. Store every Work transport input, prepared request, private-role envelope and retained command result below one transaction workspace. Before writing its first file, call `<work-cli> workspace create --workflow-id <workflow-id> [--requirement-id <requirement-id>]`. The CLI exclusively allocates `outputs/work/transactions/<requirement-id|pending>/<workflow-id>/<transaction-id>/`, including pending invocation, and returns `data.path` and `data.paths.inputs`, `requests`, `responses` and `envelopes`. Use those returned directories; never choose the transaction ID or assemble its namespace. Before a requirement ID exists, omit `--requirement-id`; preserve every previous pending path and byte after confirmation and allocate a new requirement-owned workspace.
2. Never place transport files directly in `outputs/work`, reuse another transaction's directory, overwrite an existing file, or resolve a path outside the project root. Existing files remain untouched. Retain successful and failed workspaces as audit, recovery and approval-fingerprint evidence; do not delete or relocate them automatically.
3. Reuse one workspace only for the uninterrupted logical transaction named by its workflow ID. A changed request, stale preview, failure requiring a user decision, separately authorized recovery, or transition from pending to a known requirement calls `workspace create` again. Formal CLI-owned journals and locks keep their existing canonical locations and are not transport files.
4. Preserve original input filenames, formats and exact bytes in `data.paths.inputs`, including binary PDF or other attachments. Put each semantic or CLI-prepared transport request in `data.paths.requests/<NNN>-<command>.json`, each complete CLI result in `data.paths.responses/<NNN>-<command>.json`, and each private-role envelope in `data.paths.envelopes/<NNN>-<role>.json`. Start at `001`, use distinct increasing steps for later commands or roles, and create every file exclusively. Preserve the same approved request for apply/recover; retain each invocation's response under a fresh step. Never overwrite a prior result or place formal Source, TASK, Attempt, Correction, receipt or journal artifacts in transport groups.
