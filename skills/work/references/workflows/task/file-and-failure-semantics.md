# File and failure semantics

1. One requirement's sole discussion authority is `outputs/work/discussions/<requirement-id>/session.json`, with immutable `history/<revision>/session.json`. Current is the sole commit point. Validate its exact corresponding history and predecessor chain; never promote a highest numbered directory or use retired outputs as fallback.
2. Hold `outputs/work/runtime/locks/<requirement-id>/discussion.lock` across reread, authorization/revision checks, immutable history creation, verification, pending verification, current replacement and readback. Exclusive creation binds its unique owner to the verified requirement and canonical project root. Explicit release removes only matching owner evidence after success or a controlled error; killed or unknown owners and legacy locks remain blocking until reviewed offline handling with all writers stopped. Never infer ownership from age, PID or the absence of an active old OS mutex. Preserve partial history and observed files after interruption. Do not skip revisions, overwrite conflicts, delete evidence or manufacture a successful save.
3. For stale revisions, read committed current and review the difference before a new operation. For an interrupted operation, use `discussion recover` with exactly one original initial Session or original local operation; recover only matching preserved bytes. Operation deduplication precedes stale-version rejection for an identical already committed operation.
4. Any failed or unverified save blocks the next question. Report `saved: false`, the last verified revision when available, operation identity and check/recover requirement. A process stopping after current commit must recover the same committed operation without adding a revision.
5. Formal publication uses the exact complete approved TASK index/items and initial Execution. It holds the Discussion owner, then the same requirement's `execution.lock`, without reacquiring the Discussion owner or using a separate publication lock. It rechecks Session, Source, instructions, paths and approval before writes; failure to acquire the second owner explicitly releases the first. `task recover` accepts a `recover-publication` request with the same approval/evidence; preserve exact existing files, restore only missing approved bytes and reject conflicts. It grants no Execute permission.
