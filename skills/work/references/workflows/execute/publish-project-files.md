# Publish or restore a complete project-file set

1. Read every declared target, move source/destination and precondition. Prepare all final bytes in an authorized `outputs/work/transactions/` workspace. Do not edit formal project targets directly. A move has a final absent source and a complete destination; include any content changes in those final bytes.
2. Invoke `execute file-prepare` with the normal task/execution paths, user-config-root and a `work-file-transaction-request` whose command is `{"kind":"prepare","attempt_id":"ATTEMPT-001","staged_files":{"target.txt":"outputs/work/transactions/.../target.txt"}}`. Include all create/modify/destination paths exactly; do not include move sources. Prepare reads the complete set without target, lock or runtime writes.
3. Obtain approval of the complete returned `work-file-transaction-preview`, including all before/after bytes, metadata, source bindings, paths and limitations. Invoke `execute file-apply` using command kind `apply`, exact preview, its manifest approval_sha256 as approved_sha256 and nonempty authorization_evidence. It rechecks under requirement ownership, durably preserves recovery evidence, publishes and reads back the whole set.
4. Interruption can leave a visible partial tree. Preserve all runtime evidence and never mark the Task completed or automatically rerun a CMD/OP. Invoke `execute file-recovery-prepare` with command kind `recovery-prepare` and the complete transaction_identity. It checks all actual paths and immutable evidence without writing.
5. Obtain fresh restoration authorization for that exact recovery preview. Invoke `execute file-restore` with kind `restore`, transaction_identity, recovery approval_sha256 as approved_sha256 and fresh authorization_evidence. Restore returns the entire set to its original bytes, existence and supported permissions. Unknown external changes stop the entire restore. Interrupted restore can reenter after a new preview and authorization.
6. Supported targets are ordinary writable files with existing parents on the same filesystem. Link/reparse/hard-link aliases, portable path collisions, special/readonly files and unsupported attributes are rejected. Preserve readonly state, Unix permission mode and Windows owner/group/DACL bytes including inheritance protection; prove complete security readback on publication and restoration temporaries before target writes. Windows named streams and unverifiable metadata are rejected. Timestamps and audit SACLs are outside the snapshot contract. Do not place sensitive files or credentials in staging/recovery material. No filesystem-wide instantaneous swap or control over external writers is promised.
7. Work has no enforceable sandbox for arbitrary processes. For file-changing Tasks and Discussion-derived collections it rejects unisolated CMD, automated VAL and local/external OP at record reservation/process preparation; an empty file list does not prove isolation. Use explicitly authorized host staging preparation and manual VAL, or return to planning for a verified isolation/effect capability. Retained fileless collections without Discussion provenance preserve legacy execution outside the new guarantee. Completed Attempt close recovery rechecks retained project-file publication and stops on drift; older approved record transactions without project-file evidence keep forward recovery.
