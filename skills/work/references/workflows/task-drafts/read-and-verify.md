# Read and verify


Run `<work-cli> task draft-status --requirement-id <requirement-id>` first, adding `--task-id <task-id>` for an explicit choice. It verifies the committed index and reads only the selected historical discussion, returning counts, boundaries, pending questions and `next_action`. `confirm_task_list` starts list clarification; `confirm_start`, `confirm_resume` and `confirm_review` identify the selected discussion's confirmation point; `choose_task` requires a user choice without advancing automatically. `assemble_for_review` proposes the existing assembly validation, never formal readiness or approval; other TASK candidates have not been read. `inspect_recovery` stops continuation for inspection and separately authorized recovery, without choosing or executing a recovery transaction. The command does not validate live Plan/skill/instruction sources: complete the checks below before relying on saved decisions. Treat `required_checks` as operation names, supplying the confirmed paths, selections and other arguments required below. No action grants write or Execute authorization.

1. Read the current index with `<work-cli> task draft-read --requirement-id <requirement-id>`. This reads only the authoritative index and its historical copy, not all TASK discussions.
2. For a saved discussion, run the same command with `--task-id TASK-001`, substituting the selected ID. The CLI follows `draft_ref` and verifies the exact historical bytes. Never use the root-level `TASK-001.json` display copy as resume evidence.
3. Before relying on saved decisions or writing a checkpoint, run `<work-cli> plan validate --path "<plan-path>" --user-config-root "<user-config-root>"` with every confirmed source `--skill-root`. Compare the returned `plan_sha256`, `hierarchy_selection_sha256` and `skill_selection_sha256` with index `source`. Storage integrity alone does not verify live sources or authorize a write.
4. Run `<work-cli> task draft-check --requirement-id <requirement-id> --task-id <task-id> --expected-revision <index-revision> --plan-path "<plan-path>" --user-config-root "<user-config-root>"` with every confirmed `--skill-root`. Omit selection flags to use the TASK's stored `instruction_selection` (`selected_paths` and `references` in confirmed order). `draft-status` returns that selection and `selection_confirmation_required`; it does not validate live sources. Legacy entries without this field require an explicitly confirmed `--general-only` or repeated `--instruction-path "<confirmed-path>"`, plus all applicable `--reference` values. Do not infer a selection from notes or default a missing selection to general. Explicit flags must match an existing stored selection exactly; changes use `draft-source-update`. Require `work-task-draft-source-check/v1` with `status: valid`. This read-only check performs the Plan fingerprint comparison, skill binding check, hierarchy-subset validation and current instruction fingerprint comparison, and rejects an index changed during the check. It does not save the selection, authorize saving or prove repository evidence is current.
5. Load only the selected TASK's applicable instructions and one assigned full skill. Other TASKs contribute only necessary boundaries and dependency summaries; do not preload their full skills, drafts or session transcripts. Index skill IDs must remain in the validated Plan selection.
6. Any source drift or ambiguous selection stops dependent discussion and saving. Identify affected decisions and confirm the new source/selection and the update operation first. Pass a request file containing `{"reason": <confirmed-reason>, "selections": {"TASK-001": {"selected_paths": [], "references": []}, ...}}` to `<work-cli> task draft-source-update --input-file "<request-path>" --requirement-id <requirement-id> --expected-revision <current-revision> --plan-path "<plan-path>" --user-config-root "<user-config-root>"` with all Plan `--skill-root` values. Every active TASK needs an explicit selection. The tool revalidates the Plan and skills and derives fingerprints; it cannot repair a stale formal Plan or replace an unavailable skill binding. Shared source changes mark all existing discussions for review; a local instruction change marks that TASK and its downstream consumers. Retain their old decisions as review evidence, not current approval. Before resuming formalization, reconfirm affected decisions and update structured candidates. After an interrupted update, separately authorize `task draft-source-recover` with the identical request and original expected revision; recovery rejects changed sources or incomplete files. Display copies are not updated. Never overwrite hashes manually to bypass a failure.
